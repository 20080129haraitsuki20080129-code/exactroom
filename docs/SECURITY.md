# セキュリティ設計

## 脅威モデル

想定する攻撃者は次のとおりです。

| # | 攻撃者 | 目的 |
| --- | --- | --- |
| A | 部屋に参加できる解答者 | 模範解答を盗む / 他人になりすます / 提出を改竄する |
| B | 部屋コードだけを知る第三者 | 部屋に侵入する / 出題者になりすます |
| C | 無関係な第三者 | サーバを落とす / 大量に部屋を作る |
| D | ネットワーク経路上の攻撃者 | 通信を盗聴・改竄する(HTTPS 前提で対処) |

---

## 1. 模範解答の秘匿(最重要)

**設計上の保証**

1. 模範解答は `problems.answer_latex` にのみ保存される。
2. `app/schemas.py` の中で `answer_latex` を**出力**として持つのは
   `HostProblemDetail` ただ 1 つ。これは `/api/host/problems/{id}` でしか返さず、
   出題者トークンが必須。
3. 解答者向けの `app/routers/solve.py` は、模範解答を `judge_isolated()` に
   **渡すだけ**で、返り値からは判定結果しか取り出さない。
4. エラーメッセージの分離
   - 提出答案のパースエラー → 提出者自身の入力についての説明なので返してよい。
   - **模範解答のパースエラー → 「この問題は現在採点できません」に置き換える。**
   - 判定内部の `reason` / `detail` は**解答者に返さない**(出題者のみ)。
5. `SubmissionResult` が持つフィールドは
   `submission_id` / `problem_id` / `verdict` / `message` / `created_at` /
   `remaining_submissions` のみ。

**検証**

`tests/test_secrecy.py` が次を自動で確認します。

- 問題一覧・提出応答・自分の履歴のいずれにも模範解答の文字列が現れない
- 正解・不正解・パースエラー・ゼロ除算・長すぎる入力など複数の経路で漏れない
- 模範解答が壊れている問題に提出しても、その内容がエラーに出ない
- 解答者トークンで出題者 API を呼べない(403)
- 別の部屋の出題者トークンでは覗けない
- 未認証では何も読めない(401)

**残る情報漏洩(原理的に避けられないもの)**

判定結果そのものが 1 回につき 1 ビットの情報を与えます。
何度も提出すれば模範解答を絞り込めます。対策として

- 部屋ごとに **1 問あたりの提出回数上限**(`max_submissions_per_problem`)
- **連続提出のクールダウン**(`submission_cooldown_sec`、既定 3 秒)
- IP ごとの提出レート制限

を用意しています。重要な試験では提出回数上限を設定してください。

## 2. 認証・認可

### 出題者

- 秘密キーは **PBKDF2-HMAC-SHA256、20 万回、16 バイトソルト**でハッシュ化。
  平文もリバーシブルな形も保存しません(`app/security.py`)。
- 照合は `hmac.compare_digest` による定数時間比較。
- 失敗時は**最低 0.3 秒**待たせ、さらに IP あたり毎分 10 回に制限。

### 解答者

- ログイン不要。部屋コード + 名前で参加します。
- 既定(`rejoin_policy=open`)では、同じ名前を入れれば同じ参加者として扱われます。
  **教室内でのなりすましは原理的に防げません**。防ぎたい場合は設定を
  `code`(復帰コードが必要)に変更してください。

### セッション

- **HMAC-SHA256 で署名した独自形式のトークン**(JWT ではありません)。
  トークンに使える文字は base64url + `.` のみに制限しています
  (HTTP ヘッダは latin-1 で解釈されるため、非 ASCII バイトを含む
  `Authorization` ヘッダで内部エラーを起こせないようにするため)。
  ペイロードは `role` / `room_id` / `code` / `participant_id` / `iat` / `exp` / `jti`。
- Cookie ではなく `Authorization: Bearer` ヘッダで送るため、
  **CSRF の余地がありません**(CORS も `allow_credentials=False`)。
- 保存先は `sessionStorage`(タブを閉じれば消えます)。
- サーバ側は毎回、トークンの `room_id` と `code` が DB と一致するかを確認します。

## 3. 入力の安全性

### TeX パース

- `eval` / `exec` / `compile` / `__import__` / `sympify(文字列)` /
  `sympy.parsing.latex` を**一切使いません**。
- トークナイザが受け付ける文字は正規表現のホワイトリストのみ。
  それ以外(`'`, `@`, 制御文字、絵文字など)は即エラー。
- コマンドもすべてホワイトリスト。未知のコマンドは
  「未対応のコマンド `\xxx` が含まれています」で拒否します。
- `tests/test_security.py` が **AST を解析**して、`app/` 全体で禁止関数を
  呼んでいないことを機械的に検証します。

### API 入力

- Pydantic による型・長さの検証(答案 500 文字、問題文 2000 文字など)。
- SQL は SQLAlchemy のバインドパラメータのみ。文字列連結は使いません。
- レスポンスはすべて JSON。`Content-Type: application/json` なので、
  ブラウザが HTML として解釈することはありません。

## 4. DoS 対策

| レイヤ | 対策 |
| --- | --- |
| HTTP | IP ごとのスライディングウィンドウ制限(部屋作成/時、参加・ログイン・提出/分) |
| 部屋 | 提出クールダウン、1 問あたりの提出上限、問題数上限 |
| パース | 入力 2000 文字 / 1500 トークン / ネスト 60 / 指数 ±1000 / 階乗 500 / 整数 2000 桁 |
| 判定 | 式のコストに応じて重い変形(`simplify`, `factor` 等)を自動的に打ち切る |
| 実行 | **別プロセス**で実行し、ハードタイムアウト(既定 8 秒)で強制終了。プールは自動復旧 |
| 添字 | `a_{...}` の中身は「ラベル」として扱い、展開前に複雑さを検査(演算数 16 / 指数 8 / 変数 4 まで)。以前は `a_{(x+y+z+w)^{200}}` のような 20 文字程度の入力で多項式展開が爆発し、ワーカーが OOM で落ちていた |

`tests/test_security.py::test_pathological_inputs_are_fast` が、
`2^{999999}` / `1000000!` / `x` を 400 個並べた式などを 5 秒以内に処理することを検証します。

> 実測では、対策前に 63 秒かかっていた `x^400` 系の入力が 0.02 秒になりました。

## 5. Web セキュリティヘッダ

`app/main.py` のミドルウェアが全レスポンスに付与します。

| ヘッダ | 値 |
| --- | --- |
| `Content-Security-Policy` | `default-src 'self'`、`script-src 'self' <CDN>`、`object-src 'none'`、`frame-ancestors 'none'`、`base-uri 'none'` |
| `X-Content-Type-Options` | `nosniff` |
| `X-Frame-Options` | `DENY` |
| `Referrer-Policy` | `no-referrer` |
| `Permissions-Policy` | `geolocation=(), microphone=(), camera=()` |
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains`(本番のみ) |
| `Cache-Control` | `no-store`(`/api/` 配下) |

CSP に `'unsafe-inline'` を含むのは `style-src` だけです(KaTeX と MathLive が
インラインスタイルを使うため)。**スクリプトのインライン実行は禁止**しており、
HTML には `<script>` タグの本文がありません。

---

## 6. XSS 対策

- フロントエンドは `innerHTML` / `insertAdjacentHTML` / `document.write` を
  **一切使いません**。すべて `textContent` と `createElement` です。
- 数式の表示は KaTeX に `trust: false`(`\href` や `\url` を無効化)、
  `strict: "ignore"`、`maxExpand: 200` を指定して委譲しています。
- 問題文・答案・名前はすべてテキストとして扱われます。

---

## 7. プライバシー

- 生の IP アドレスは保存しません。`HMAC-SHA256(SECRET_KEY, ip)` の先頭 16 桁のみを
  監査用に残します(`SECRET_KEY` を変えれば過去のハッシュは照合不能になります)。
- Cookie を使いません。トラッキングもアナリティクスもありません。
- 外部 API に一切データを送りません(CDN から静的ファイルを取得するだけ)。
  CDN も使いたくない場合は、MathLive / KaTeX を `static/vendor/` に置き、
  `static/js/config.js` の URL を相対パスに変えてください。

---

## 7.5. 可用性についての既知の制約

- 判定ワーカーはプールで共有しているため、誰かの判定がタイムアウトすると
  プールごと作り直されます。同時に走っていた別の人の判定は巻き添えで
  失敗しますが、**1 回だけ自動で再試行**するようにしてあります。
  それでも失敗した場合は「判定保留」になり、再提出できます。
- レート制限はプロセス内メモリなので、複数ワーカーで動かすと
  実質ワーカー数倍に緩みます(DEPLOY.md 参照)。
- `TRUST_PROXY_HEADERS=true` にすると `X-Forwarded-For` を信用します。
  **リバースプロキシの背後でのみ有効にしてください。**
  直接インターネットに公開しているサーバで有効にすると、
  クライアントが自由にヘッダを詐称してレート制限を回避できます。

## 8. 運用上の注意

1. **`SECRET_KEY` を必ず設定し、外部に出さないこと。**
   漏れるとトークンを偽造されます。変更すると全セッションが無効になります。
2. **HTTPS で公開すること。** 部屋コードと秘密キーが平文で流れます。
3. `ENVIRONMENT=production` にすると `/docs` と `/openapi.json` が無効になります。
4. 公開サーバでは `ROOM_CREATION_TOKEN` を設定して、部屋の乱立を防いでください。
5. 試験終了後は「設定」で部屋を閉じてください。
6. 複数ワーカーで動かす場合、レート制限はワーカーごとに独立します(DEPLOY.md 参照)。
7. `rejoin_policy="code"` にした部屋では、解答者が復帰コードを控え損ねると
   同じ名前で戻れなくなります。出題者は「参加者」タブの
   **「復帰コード再発行」**で救済できます。
