# ExactRoom Binary Judge

ExactRoomの数学Verdictは `AC` / `WA` の二値です。答案や問題のパース失敗、タイムアウト、worker/DB障害は数学Verdictにせず、APIの入力・処理エラーとして扱います。エラーは提出回数を消費しません。

## 判定パイプライン

1. ホワイトリスト方式のTeXパーサで式を構築します。パースに失敗した答案は `input_error`、模範解答は `problem_error` です。どちらも数値fallbackへ送りません。
2. 既存の厳密な記号比較、定義域比較、関係式の解集合比較を実行します。証明できた一致はAC、厳密な反例を得たものはWAです。
3. 記号判定で決着しない場合は、別プロセス内の高精度数値fingerprintへ進みます。
4. 数値評価に失敗した場合や必要な有効点数を確保できない場合は採点処理エラーとします。障害をWAに変換しません。

## 高精度数値fingerprint

- 計算精度は12,000桁、比較基準は最初の10,000桁です。許容差は絶対項と相対項の両方を含みます。
- 定数式は値の差を直接評価します。ExactRoomの精度規則では `1` と `1+10^{-12000}` を同一扱いし、`1` と `1+10^{-9000}` は区別します。
- 変数を含む式は64個の有効点を使い、最大256候補を試します。各変数へ独立した有理数を代入し、全変数へ同一値だけを入れる方式にはしません。
- seedはサーバー秘密鍵からHMACで導出し、問題・参加者・答案ハッシュと提出ごとの乱数を含めます。同一seedなら同一点列になり、提出が変われば点列も変化します。
- 分母、対数、偶数根、逆三角関数などの定義域を各側で確認します。両方で有効な点だけ比較に使い、片側だけ未定義となる点は非同値の根拠にできます。無効点は捨てます。
- 方程式は左右辺の数値ではなく各点の真偽値、不等式も左右辺の大小関係の真偽値を比べます。有限集合は要素の完全マッチング、順序付きリストは位置ごとに比較します。
- 1点でも許容差を超える差や真偽の違いがあればWA、必要な全点が一致すればACです。

**ACの意味に注意してください。** 数値fingerprintによるACは数学的な証明ではなく、ExactRoomが定める高信頼度の数値採点結果です。有限個の公開点だけに一致する式は理論上作れます。点列は秘密seedで隠し、答案ごとに変えますが、意図的な攻撃を数学的に不可能にするものではありません。厳密証明だけを要する試験では、この数値fallbackを有効にしない構成が必要です。

## API状態と回数

| `status` | `verdict` | 提出回数 |
| --- | --- | --- |
| `judged` | `AC` または `WA` | 消費 |
| `input_error` | `null` | 消費しない |
| `problem_error` | `null` | 消費しない |
| `timeout` | `null` | 消費しない |
| `internal_error` | `null` | 消費しない |

旧DBの非NULL制約を保つため、障害行のDB `verdict` 列には互換プレースホルダーが残る場合があります。API/UIでは `status` を優先し、これを数学Verdictとして表示しません。

## 診断情報と秘匿

提出者にはAC/WAまたは入力・処理エラーだけを返します。seed、点列、数値差、内部計算理由は返しません。出題者向け一覧には内部理由を表示できます。模範解答は解答者API・JavaScript・ネットワーク応答に含めません。

## 回帰テスト

`tests/test_numerical.py` は、記号判定からfallbackへ進むAC/WA、精度閾値、secret seedの再現性・変動、変数の複数点比較を検証します。`tests/test_security.py` は `eval` 系を禁止し、高精度評価を `numerical.py` に限定します。通常のパーサと厳密判定経路に数値近似を入れない方針は維持します。
